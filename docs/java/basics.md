# 1. Java 基礎（Q1–10）

## JVM、JDK、JRE
- **JVM**：執行位元組碼（bytecode）的虛擬機。`.java` 編成 `.class`，由各平台的 JVM 執行 →「一次編譯，到處執行」，這就是平台無關。
- **JRE** = JVM + 核心類別庫（執行用）。
- **JDK** = JRE + 編譯器 `javac` + 工具（javadoc、偵錯器…）（開發用）。

!!! warning "補充"

    Java 11 起 Oracle 不再單獨發行 JRE；現在多用 `jlink` 自製精簡執行環境。原文提到的 applet 瀏覽器外掛也早已移除。

## static
- `static` 成員屬於**類別**，不需實例就能存取；類別載入時初始化，所有實例共用。
- **static 方法不能被覆寫（override）**：覆寫靠執行期動態綁定，static 是編譯期靜態綁定。子類寫同名 static 方法叫**隱藏（hiding）**。
- **private 方法也不能被覆寫**：子類看不到它。
- **static 環境不能直接存取非 static 成員**：此時可能還沒有任何實例。

## 資料型別與自動拆裝箱
- 8 種基本型別：`byte`、`short`、`int`、`long`、`float`、`double`、`boolean`、`char`。
- **自動裝箱**：基本型別 → 包裝類別（`int` → `Integer`、`double` → `Double`）；反向叫**自動拆箱**。

!!! warning "補充（常考陷阱）"

    `Integer` 會快取 -128～127，所以 `Integer a=127, b=127; a==b` 為 true，換成 128 就是 false。包裝類別要用 `equals()` 比較；`null` 拆箱會丟 `NullPointerException`。

## 覆寫（Override）vs. 重載（Overload）

| | 重載 Overload | 覆寫 Override |
|---|---|---|
| 發生位置 | 同一個類別 | 子類別對父類別 |
| 方法名 | 相同 | 相同 |
| 參數列 | **必須不同** | **必須相同** |
| 回傳型別 | 無關 | 相同或其子型別（共變回傳） |
| 存取權限 | 無關 | **不能更嚴格**（父 `protected` → 子不能是 `private`） |
| 綁定時機 | 編譯期 | 執行期（多型） |

## 建構子
- 建立物件時呼叫；沒寫建構子時，編譯器給一個無參數的預設建構子。
- **建構子重載**：多個建構子，參數列各不相同。
- Java **沒有** C++ 那種自動產生的複製建構子（要自己寫，或用 `clone()`／工廠方法）。

## 多重繼承、介面 vs. 抽象類別
- Java 類別**只能單一繼承**，但可以**實作多個介面**。

| | 介面 interface | 抽象類別 abstract class |
|---|---|---|
| 方法 | 原本全部隱含 abstract | 可混合抽象與具體方法 |
| 數量 | 可實作多個 | 只能繼承一個 |
| 變數 | 隱含 `public static final`（常數） | 可有一般實例變數 |
| 成員可見度 | 預設 `public` | 可以是 private / protected / public |
| 實例化 | 不行 | 不行（但可以有 `main` 並執行） |
| 未實作完 | 實作類別要全部實作，否則自己得宣告 abstract | 同左 |

!!! warning "補充"

    **Java 8** 起介面可有 `default` 方法與 `static` 方法，**Java 9** 起可有 `private` 方法，所以「介面方法全是抽象的」已不成立。現代答法：介面描述「能做什麼（能力／契約）」、沒有狀態；抽象類別描述「是什麼（is-a）」，可以持有狀態與建構子。

## 值傳遞 vs. 參考傳遞（⚠️ 原文有誤）
- 原文把物件說成「參考傳遞」，這是**經典錯誤答案**。
- **正確答案：Java 只有值傳遞（pass by value）。** 傳物件時，傳的是「參考的副本」。
  - 在方法內**改物件內容**（`p.setName("x")`）→ 外部看得到，因為兩個參考指向同一個物件。
  - 在方法內**讓參數指向新物件**（`p = new Person()`）→ 外部不受影響，這證明不是參考傳遞。
